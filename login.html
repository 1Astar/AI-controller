本页职责：仅「扫码识别」，缓存设备信息；不绑定、不配网、不写主用户。

扫码时序（本页只走前两步）

sequenceDiagram
  participant 用户
  participant App
  participant 云端

  用户->>App: 扫出厂贴纸（SN + token）
  App->>云端: 查询 SN 当前信息
  云端-->>App: 型号、联网方式、经销商、是否可绑
  Note over App: 本页到此为止，缓存 pending<br/>登录后进 index 继续配网
本页写入 cledic_pending_bind_v1：
  code · netType · modelLabel · locationName
  awaitOnboarding = true

登录/注册成功 → index?continueOnboarding=1
  从配网第 ② 步联网开始，第 ③ 步完成才写主用户

前后端约定仅供参考，能实现同等功能即可；完整时序与接口见后台 📝「扫码解析接口约定」。

为何不在登录页绑定？

  • 未登录无法确定 owner 手机号
  • 需先完成联网（WiFi 填网 / 4G 连云，均为第 2 步）再命名设备
  • 避免未配网设备误占 owner 导致重复绑定工单

未登录扫码后：提示先登录/注册；pending 保留，登录后继续。

已有主用户：若 pending 完成后检测到 owner 冲突 → 弹窗 + 写 bind_conflict（见 index 📝 配网）。

完整时序与三场景：用户端「添加设备 / 配网」弹窗 📝；接口细节见后台 📝「扫码解析接口约定」。
