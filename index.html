      扫码时序图

      sequenceDiagram
  participant 用户
  participant App
  participant 云端
  participant 经销商后台

  用户->>App: 扫出厂贴纸（只含 SN + token）
  App->>云端: 查询 SN 当前信息
  云端-->>App: 型号、联网方式、当前经销商、是否可绑
  App->>用户: 走配网 / 绑定流程
  Note over 云端,经销商后台: 后台把设备迁给新经销商后<br/>下次扫码自动返回新经销商

      以下前后端说明仅供参考，能实现同等功能即可；完整版见后台 📝「扫码解析接口约定」。

      后端接口（摘要）

      • scan-context：SN → 型号、联网、经销商、是否可绑
      • device.dealer_id 可空；迁移记审计；bind_token 可作废
      • 绑定完成写 device_access（主用户），与 dealer 分开

      前端逻辑（摘要）

      扫码 → SN/型号/WiFi·4G → 配网 → 命名 → 完成时才绑主用户
经销商提示：登录手机号匹配 或 scan-context.dealer

      App 内三步向导（WiFi / 4G 均走完整三步，第 2 步不跳过）

      ① 扫码/输入 SN
   └─► GET scan-context（原型读 localStorage）
       返回 model · net_type · dealer · bind_allowed · owner_phone

② 联网（配网）— 两种路径，同一进度步骤
   ├─ WiFi：选 SSID + 密码 → 点「确认联网」→ 进度条走完
   └─ 4G：不填 WiFi；展示 SIM 注册 / 云端连接进度
       （网络初始化 → 已连接云端 → 自动进入 ③）

③ 命名确认
   └─► 点「完成」→ 写入 device_access（主用户）
       与 dealer_id 分开存储；此时才绑定 owner

      仅原型 配网弹窗内虚线框「仅原型」说明 — 给产品/开发对齐，正式版 App 不上线。

      登录页联动

      login 页仅「扫码识别」→ 缓存 cledic_pending_bind_v1
  awaitOnboarding=true
登录/注册成功 → index?continueOnboarding=1
  自动带入 SN，从第 ② 步联网开始，无需重复扫码

      绑定时机：普通用户第 3 步「完成」才写主用户。经销商「登记为经销设备」：第 1 步写 dealer、owner 仍空，可继续第 ②③ 步演示配网（仅联网+命名，不写 owner）。「绑定为我的设备」扫码时即写 owner。

      联网 · 下控 · 归属（三件独立的事）

      联网状态：设备是否已配网/在线（离线不可远程下控）
控制权限：谁有权发指令（与 owner 是否为空无关；经销商见三态规则）
设备归属：dealer_id（经销商）与 ownerPhone（主用户）两层，互不等同

      经销商扫码（特殊路径）

      登录手机号 = 经销商账号 phone
扫码后 App 识别 dealer → 弹窗双选（见界面「仅原型」虚线框说明）
  登记为经销设备 → 写 dealer、owner 空 → 继续配网演示（联网后可下控，仍不写 owner）
  绑定为我的设备 → dealer + 经销商 phone 为主用户；可继续配网命名（自用安装）
  取消 → 不变更归属，可继续仅查看

与农户配网互斥场景见 📝「主用户与子用户」

      冲突与拦截

      已有主用户 + 他人完成配网 → 提示联系管理员，写 bind_conflict 待处理
两经销商认领同一 SN → 后台「经销商归属冲突」
bind_token 无效/过期 → scan-context.bind_token_valid=false → 拒绝绑定

      业务场景（动态归属）

      ① 出厂不绑经销商：registry 仅 SN+型号+net_type → 后台归属后 scan-context 返回经销商，贴纸不换。

      ② 换经销商：后台迁移改 dealer_id；新扫码归新经销商；老用户数据/主用户保留，工单告警路由新经销商；App 可弹「服务已由 XX 承接」（正式版待做）。

      ③ 工单售后：创建工单带 device_sn，服务端查当前 dealer_id 写入归属。

      接口完整说明：后台 📝「扫码解析接口约定（给后端）」。

      设备来源

      扫码配网完成 → 写入 bindings + 本地设备列表
被分享加入   → 仅多一条绑定，非 owner
经销商扫码   → 设备进经销商后台台账，App 列表是否展示由产品定

      经销商首次扫码

      登记为经销设备 → dealer 归属 + 可演示配网（联网后下控，owner 仍空）
绑定为我的设备 → dealer + 经销商为主用户；他人扫码提示已绑定
出售前须解绑主用户

      解绑规则

      主用户 / 子用户「解绑设备」
  → 主用户：立即清空绑定+子用户，设备变「待绑定」，后台写追溯记录（非待办）
  → 子用户：仅解除自己的分享关系

      分享：主用户在设备卡片点「分享」→ 生成分享码/链接；对方接受后为子用户（权限见 📝 主用户与子用户）。

      多设备切换：列表点击切换当前设备；工作台/告警/远程均跟当前 SN。

      三层身份（勿混淆）

      经销商（dealer_id）  →  服务归属、工单路由、后台/App 下控（项目范围内）
主用户（ownerPhone） →  扫码配网完成者
子用户（share）      →  被分享成员

      下控权限（启停 / 换档 / 复位等）

      • 主用户、子用户：均可下控
      • 经销商：见下方三态规则

      经销商下控三态

      主用户为空     → 经销商可下控（须设备已联网，离线不可下控）
主用户已绑定   → 经销商下控自动关闭
售后工单期间   → 主用户工单内「授权经销商远程协助」后临时恢复（48h，关单失效）

      联网 · 下控 · 归属：三者独立。经销商演示 = 登记 + 演示配网联网 + owner 仍空 + 下控演示。

      主用户 vs 子用户（核心差异）

      相同：均可远程下控、看数据/告警、解绑自己的设备关系
不同：仅主用户可「取消子用户的绑定」、管理分享成员、授权经销商售后下控

      典型场景

      ① 家人共用：主用户分享 → 子用户可下控；主用户可随时取消对方绑定。

      ② 设备转手：须后台「更换主用户」或原 owner 解绑后新用户重扫配网。

      ③ 经销商代运维：经销商对归属设备下控；不取代 owner 身份。

      后台处理重复绑定见 admin 📝「绑定/解绑待处理」。

      复位策略

      • allow → 按钮「尝试复位」
      • cautious → 按钮「重新检测」
      • hidden → 不展示复位，仅「联系维修 / 我知道了」

      用户操作时序

      尝试复位 (allow)
 用户 ──► App ──► 云端 ──► 控制器「故障复位」
         清除锁存 → 重新自检 → 可恢复运行

重新检测 (cautious)
 用户 ──► App ──► 云端 ──► 控制器「重新检测」
         仅复测；异常仍在则继续告警

hidden：不下发复位指令，引导联系经销商/提工单

      权限：主用户、子用户、经销商均可下控；复位按钮仍受告警 resetPolicy（allow/cautious/hidden）约束。

      售后联动：告警页「联系维修」→ 创建工单（带 device_sn）→ 路由当前 dealer，见后台 📝 工单管理。

      原型：本地模拟指令并清除告警，不连真机。
